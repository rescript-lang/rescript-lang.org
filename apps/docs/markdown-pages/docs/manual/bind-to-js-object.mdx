# Bind to JS Object

JavaScript objects are a combination of several use-cases:

- As a "record" or "struct" in other languages (like ReScript and C).
- As a hash map.
- As a class.
- As a module to import/export.

ReScript cleanly separates the binding methods for JS object based on these 4 use-cases. This page documents the first three. Binding to JS module objects is described in the [Import from/Export to JS](./import-from-export-to-js.mdx) section.

## Bind to Record-like JS Objects

### Bind Using ReScript Record

If your JavaScript object has fixed fields, then it's conceptually like a ReScript record. Since a ReScript record compiles to a clean JavaScript object, you can definitely type a JS object as a ReScript record!

<CodeTab labels={["ReScript", "JS Output"]}>

```res
type person = {
  name: string,
  friends: array<string>,
  age: int,
}

@module("MySchool") external john: person = "john"

let johnName = john.name
```

```js
import * as MySchool from "MySchool";

let johnName = MySchool.john.name;

export { johnName };
```

</CodeTab>

External is documented [here](./external.mdx). `@module` is documented [here](./import-from-export-to-js.mdx).

If you want or need to use different field names on the ReScript and the JavaScript side, you can use the `@as` decorator:

<CodeTab labels={["ReScript", "JS Output"]}>

```res
type action = {
  @as("type") type_: string
}

let action = {type_: "ADD_USER"}
```

```js
let action = { type: "ADD_USER" };

export { action };
```

</CodeTab>

This is useful to map to JavaScript attribute names that cannot be expressed in ReScript (such as keywords).

It is also possible to map a ReScript record to a JavaScript array by passing indices to the `@as` decorator:

<CodeTab labels={["ReScript", "JS Output"]}>

```res
type t = {
  @as("0") foo: int,
  @as("1") bar: string,
}

let value = {foo: 7, bar: "baz"}
```

```js
let value = [7, "baz"];

export { value };
```

</CodeTab>

### Bind Using ReScript Object

Alternatively, you can use [ReScript object](./object.mdx) to model a JS object too:

<CodeTab labels={["ReScript", "JS Output"]}>

```res
type person = {
  "name": string,
  "friends": array<string>,
  "age": int,
}

@module("MySchool") external john: person = "john"

let johnName = john["name"]
```

```js
import * as MySchool from "MySchool";

let johnName = MySchool.john.name;

export { johnName };
```

</CodeTab>

### Bind Using Special Getter and Setter Attributes

Alternatively, you can use `get` and `set` to bind to individual fields of a JS object:

<CodeTab labels={["ReScript", "JS Output"]}>

```res
type textarea
@set external setName: (textarea, string) => unit = "name"
@get external getName: textarea => string = "name"
```

```js
/* This output is empty. Its source's type definitions, externals and/or unused code got optimized away. */
```

</CodeTab>

You can also use `get_index` and `set_index` to access a dynamic property or an index:

<CodeTab labels={["ReScript", "JS Output"]}>

```res
type t
@new external create: int => t = "Int32Array"
@get_index external get: (t, int) => int = ""
@set_index external set: (t, int, int) => unit = ""

let i32arr = create(3)
i32arr->set(0, 42)
Console.log(i32arr->get(0))
```

```js
let i32arr = new Int32Array(3);

i32arr[0] = 42;

console.log(i32arr[0]);

export { i32arr };
```

</CodeTab>

## Bind to Hash Map-like JS Object

If your JavaScript object:

- might or might not add/remove keys
- contains only values that are of the same type

Then it's not really an object, it's a hash map. Use [Dict](/docs/manual/api/stdlib/dict), which contains operations like `get`, `set`, etc. and cleanly compiles to a JavaScript object still.

## Bind to a JS Object That's a Class

Use `new` to emulate e.g. `new Date()`:

<CodeTab labels={["ReScript", "JS Output"]}>

```res
type t
@new external createDate: unit => t = "Date"

let date = createDate()
```

```js
let date = new Date();

export { date };
```

</CodeTab>

You can chain `new` and `module` if the JS module you're importing is itself a class:

<CodeTab labels={["ReScript", "JS Output"]}>

```res
type t
@new @module external book: unit => t = "Book"
let myBook = book()
```

```js
import * as Book from "Book";

let myBook = new Book();

export { myBook };
```

</CodeTab>

### Represent Class Inheritance

ReScript has no class declarations, but bindings can model existing JavaScript inheritance using **phantom type parameters** and [polymorphic variants](./polymorphic-variant.mdx#lower-bound-). Suppose `animals.js` exports the hierarchy `Animal → Mammal → Dog`:

```js
// animals.js
export class Animal {
  constructor(name) {
    this.name = name;
  }

  getName() {
    return this.name;
  }
}

export class Mammal extends Animal {}

export class Dog extends Mammal {
  bark() {
    return "Woof!";
  }
}
```

Declare the base type and its methods in `Animal.res`:

```res file=Animal.res
type t<'a>

@send external getName: t<'a> => string = "getName"
```

The **phantom type parameter** `'a` tracks the class in the type system without adding data to the JavaScript object.

In `Mammal.res`, require the `#Mammal` tag while allowing subclasses to add their own tags:

```res file=Mammal.res
type t<'a> = Animal.t<[> #Mammal] as 'a>
```

The constraint `[> #Mammal] as 'a` means `'a` must include at least `#Mammal`.

In `Dog.res`, close the set of tags and add its constructor and methods:

```res file=Dog.res
type t = Mammal.t<[#Dog | #Mammal]>

@new @module("./animals.js") external make: string => t = "Dog"
@send external bark: t => string = "bark"
```

Parent methods accept subclass instances directly:

```res
let dog = Dog.make("Rex")

let name = dog->Animal.getName
let sound = dog->Dog.bark
```

`Animal.getName` accepts any `Animal.t<'a>`, including `Dog.t`. `Dog.bark` accepts only `Dog.t`, so it cannot be called on other animals.

The tags are used only during type checking. The generated JavaScript uses the original class instances.

#### Interfaces

If you add a [`.resi` interface](./module.mdx#signatures), expose the same type parameter and alias so callers can use parent methods. For example, `Mammal.resi` should contain:

```res file=Mammal.resi
type t<'a> = Animal.t<[> #Mammal] as 'a>
```
